Getting started

  1. Check the requirements. Rider 2026.2 or later; the .NET 10 SDK on the PATH Rider loads from your shell (the graph window says so when it is missing); a solution file named after the project (<Name>.sln or <Name>.slnx) in the project's root directory.
  2. Install. Settings → Plugins → Marketplace → Diff Graph → Install, or install the zip from a release through ⚙ → Install Plugin from Disk.
  3. Activate a license. Click the lock button (Enter License) in the tool window's toolbar, enter a license or start a trial on JetBrains Marketplace, then click Refresh.
  4. Make a change. Edit C# files yourself or let your AI assistant do it. The graph shows everything that differs from HEAD.
  5. Open the graph. View → Tool Windows → Diff Graph, or Ctrl+Shift+Alt+G. The first analysis loads the solution and takes a moment; after that the graph follows your edits on its own.
  6. Read the change. Start at the left: those types depend on nothing else in the change. Click a type to open its diff, click an edge to see the lines that create that dependency.
  7. Stage what you reviewed. Right-click a type or an edge → Stage / Unstage. The badges show what is staged, partly staged or unstaged.
  8. Cut the noise. Hide tests, hide unchanged neighbours, show changed edges only, pick edge kinds, or find a type by name.

Graph looks stale or stuck? Refresh in the tool window's toolbar restarts the analyser and analyses the change again.

How it works

Each side of the change is checked out into a temporary worktree, the solution is restored and loaded by Roslyn, and a symbol graph is built per side: the types in the repository and the dependencies between them. The two graphs are compared and the difference is drawn. A side's graph is cached by content, so an unchanged working tree is read from the cache. Only the projects holding changed files are compiled.

Limits

  • C# only. Other changed files are listed with their hunks but have no node.
  • A dependency Roslyn cannot resolve (a package that did not restore, generated code not on disk) is missing from the graph.
  • Both sides must load: a commit that does not restore gives no graph.
